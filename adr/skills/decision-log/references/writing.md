# Decision log の書き方（`write` のときに読む）

## ファイルの形

置き場所 1 と 3 のファイルの形は、組織の記録（`records/decision-logs/`）と同じにする。あとでそのまま移せる（番号は移す先で振り直す）。

- ファイル名は `0001.md` か `0001-auth-pkce.md`。先頭の 4 桁が番号で、フォルダーの中で最大の番号の次を使う。
- 記録を指すときは `DL-1`（決定は `DR-`、決め方は `DF-`、Q&A は `Q-`）と書き、`#1` とは書かない（GitHub が issue・PR へのリンクにするため）。
- 先頭にフロントマター、その下に `# [<リポジトリ名>] <何が変わったか>`、その下に本文を置く。`records.py` を使うときは、`--body-file` に下の例から `# ` の行を除いたものを渡し、タイトルは `--title` で渡す。
- 追記は末尾に `## 追記 YYYY-MM-DD（書いた人）` の見出しで足す。最初の追記の前にだけ `---` を置く。前の行は書き換えない。

## ファイル全体の例

````markdown
---
kind: log
category: reliability
repos: [payment-api]
paths: [src/payment/http/]
keywords: [MAX_RETRIES, retry, backoff]
---

# [payment-api] リトライの上限が 3 から 5 になった

> 過去の観察である。決定ではなく、何も縛らない。

## 起きたこと

- C1 2025-03-04 いまも同じ：リトライの上限が 3 から 5 になった。履歴：[PR #101](<PR の URL>) ／ 現在：[`client.py:12` @`abc1234`](<行の URL>)
- C2 2025-03-04 置き換え済み：失敗時は固定 1 秒待つようになった。履歴：[PR #101](<PR の URL>) ／ 現在：[PR #140](<PR の URL>) で指数バックオフに変わった

## 理由

不明（記録に書かれていない）。

## 関わった人

PR の記録から。決めた人とは限らない。

- PR #101：作成 @alice（2025-03-03）、承認 @bob（2025-03-04）、マージ @bob（2025-03-04）

## 分かっていないこと

- なぜ 5 にしたか。障害対応か、相手先の要望か（@alice に聞く）。

## 元の場所

- （上で触れていない出典だけ。例：議論のあった issue、Slack のリンク。なければこの見出しごと書かない）

## 関係する記録

- （関係する記録を `DR-12`、`DL-3` の形で。なければこの見出しごと書かない）
````

## 書き方

- **文体**：である調。タイトルで言ったことを本文で繰り返さない。同じリンクやリポジトリ名を何度も書かない。
- **見出し**：タイトルは `#`、本文の節は `##`（太字を見出しの代わりにしない）。節の順は例のとおり。中身のない節は書かない。「理由」と「分かっていないこと」は、ないなら「不明」「なし」と書いて残す。
- **起きたこと**：変更ごとに 1 行。`C<番号> <日付 YYYY-MM-DD> <状態>：<何が変わったか>。履歴：<リンク> ／ 現在：<リンク>`。番号は Decision log の中で一意にし、振り直さない。日付は索引が読む。
- **理由**：1 行目は「記録あり：<要約>（<出典>）」「推測：<内容>」「不明（記録に書かれていない）」のどれか。他の案が書かれていれば 2 行目から書く。1 行目は索引が読む。
- **関わった人**：PR ごとに 1 行。作成（`author`・`createdAt`）、承認したレビュー（`reviews` の `APPROVED`・`submittedAt`）、マージ（`mergedBy`・`mergedAt`）。役割は PR や `config.yaml` の roles に書かれているときだけ `@bob（SRE）` と添える。git だけのときは、コミットの author と日付を書き「レビューは見ていない」と添える。決めた人を書けるのは、決定の言葉と一緒に書かれているときだけである。
- **リンク**：PR・issue・コミット・コードの行はリンクにする。PR は API の `url`。コミットとコードの行は `git remote get-url origin` から作り、ハッシュで固定する（`/commit/<完全なハッシュ>`、`/blob/<ハッシュ>/<パス>#L12`。GitLab は `/-/` を挟む）。作れなければ「リンクなし」と添える。
- **フロントマター**：ツールが読む項目だけを置く。`kind`・`category` は索引と `records.py index`、`repos`・`paths`・`keywords` は adr-guard が読む。リストは 1 行の `[a, b]`。`paths` は前方一致で照らすパス。`keywords` は、本文に出てこないが差分に実際に出てくる言葉（識別子、設定名、テーブル名、言い換え）。

## 追記の印

追記の 1 行目を次の印で始めると、索引と `records.py` が読む。それ以外の追記は印なしで書く（例：「C1 の状態を競合に変更：理由、証拠」）。

| 印 | 使うとき | 2 行目から |
|---|---|---|
| `**分類を更新**（YYYY-MM-DD）` | 分類を直す | `category: <新しい分類>` |
| `**探し方を更新**（YYYY-MM-DD）` | `paths`・`keywords` を直す | 変える項目だけを、最新の一覧まるごとで |
| `**分かった**（YYYY-MM-DD）：「<分かっていないことの問い>」` | 理由が分かった | 答え、答えた人（アカウント名）、元の場所のリンク。なければ「元の場所なし」 |
| `**決定になった**（YYYY-MM-DD）：DR-<番号>` | 人がこの観察をもとに決定を作った | なし |
| `**終了**（YYYY-MM-DD）：<理由>` | 取り下げる（重複、誤りなど） | なし |

「分かった」の答えに、決定の言葉と決めた人まで含まれていれば、報告の「決定の候補」にも回す。

## 索引

`records.py` を使うときは索引のファイルを持たない（`records.py index` が毎回並べる）。それ以外の置き場所では、書いたあとに必ず次を実行する。手で書かない。

```sh
python3 <このスキルのフォルダー>/scripts/build_index.py <置き場所>
python3 <このスキルのフォルダー>/scripts/build_index.py <置き場所> --check   # 索引が最新で、形の崩れがなければ終了コード 0
```

スクリプトがすること：分類（`category` に「分類を更新」を重ねたもの）ごとに見出しを分け、「起きたこと」のいちばん古い日付の古い順に並べる。「理由」の 1 行目が「不明」で「分かった」の追記がないものに `・理由不明` を付け、「終了」の追記があるものは最後の「取り下げ」に移す。

```markdown
## 性能・信頼性（reliability）

- 2024-11-20 [DL-4](0004.md) 外部 API のタイムアウトが 10 秒から 5 秒になった・理由不明
- 2025-03-04 [DL-1](0001.md) リトライの上限が 3 から 5 になった
```

ほかのブランチと `README.md` が衝突したら、手で直さない。既定のブランチを取り込み、番号が重なっていれば自分の側のファイルの番号を振り直してから、スクリプトで作り直す。

## 監査の記録

全体の監査を頼まれ、時系列と候補の一覧（ledger）を残すように言われたら、同じ置き場所に `[<リポジトリ名>] 監査 YYYY-MM-DD`（フロントマターは `kind: audit`）を書く。中身は範囲、広さと深さ、確かめた手順、未調査の範囲である。
