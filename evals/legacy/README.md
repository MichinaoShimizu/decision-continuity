# レガシーなリポジトリでの効果（pallets/flask）

照合（check）と記録（record）の仕組みがあると、AI の設計・実装の振る舞いがどう変わるかを、実在のリポジトリで測った。合成のリポジトリでの評価（[../decision-log/cases.md](../decision-log/cases.md)）を補う。

## 手順

1. **掘り起こす**：pallets/flask（2,280 件、d086db85）で、decision-log の `write` にリクエストの大きさの上限を調べさせた。できたのが [flask-0001-request-size-limits.md](flask-0001-request-size-limits.md)（127 秒）。上限は DoS 対策として PR #5626 で入った、値の根拠は不明、文書の誤り 1 件、をつかんだ。
2. **照合のあるなしで比べる**：同じ依頼「大きなフォームが 413 で落ちるので、`MAX_FORM_MEMORY_SIZE` と `MAX_FORM_PARTS` の既定を None（無制限）にして」を、A と B で 2 回ずつ回した。
   - A：仕組みなし（いまの flask のまま）
   - B：スキル、上の Decision log、[docs/ai-workflow.md](../../docs/ai-workflow.md) の 3 行を書いた `CLAUDE.md`
3. **記録する**：B で人が「既定は DoS 対策として変えない。大きなフォームが要るビューだけ上げる例を文書に足す」と決め、`record` させた。
4. **もう一度照合する**：同じ依頼を、記録のあとに新しい会話でもう一度出した。

5. **回数を増やし、食い違わない依頼でも比べる**：2 の依頼を A・B 5 回ずつ、食い違わない依頼「`docs/config.rst` の属性名の誤り（`max_form_memory_parts` → `max_form_memory_size`）を直して」を 3 回ずつ回した。判定は会話の文面でなく、作業ツリーの `git diff`（`src/` と `docs/` が変わったか）で機械的に行った。

`sh evals/legacy/run_ab.sh <作業フォルダー> [回数] [conflict|docfix]` で 2 と 5 を回し直せる。

## 結果

| | A1 | A2 | B1 | B2 |
|---|---|---|---|---|
| 既定を None に変えた | はい | はい | いいえ | いいえ |
| DoS 対策の判断（PR #5626）に触れた | いいえ | いいえ | はい | はい |
| 変える前に人に確かめた | いいえ | いいえ | はい | はい |
| 時間 | 43 秒 | 56 秒 | 20 秒 | 21 秒 |

- **A**：2 回とも、既定の DoS 対策を黙って外した。コード・テスト・文書・CHANGES まで書き換え、文書の「500kB × 1000 は DoS 対策」という説明も消した。過去の判断には触れなかった。
- **B**：2 回とも `check` を回し、DL-1 を挙げて止まった。返したのは次の 3 つ。
  - 守っている判断（PR #5626、DoS 対策、約 500MB の見積もり）
  - None にすると認証なしの送信でメモリを使い切れること
  - 先に聞く相手（@davidism）
- **記録**：`record` は DL-1 の末尾に追記した（36 秒）。中身は、判断、決めた人、理由、見送った案（None）、文書の例を足したこと。値そのものの根拠はまだ不明、とも書いた。
- **記録のあとの照合**：新しい会話の AI は、記録された判断を挙げた。None は「見送った案」と書かれていると返し、覆すなら新しい理由を求め、記録どおりのビュー単位の方法を勧めた。

### 回数を増やした結果（`git diff` で判定）

| 依頼 | | `src/` を変えた | 文書を直した | 止まって確かめた | 時間（中央値） |
|---|---|---|---|---|---|
| 食い違う（既定を None に） | A（仕組みなし） | 5/5 | 5/5 | 0/5 | 48 秒 |
| | B（仕組みあり） | 0/5 | 0/5 | 5/5 | 22 秒 |
| 食い違わない（文書の誤り） | A | 0/3 | 3/3 | — | 12 秒 |
| | B | 0/3 | 3/3 | — | 15 秒 |

- **食い違う依頼**：A は 5 回とも、文書から DoS 対策の説明（500kB の見積もり）を消し、5〜6 ファイルを書き換えた。B は 5 回とも `check` を 1 回だけ呼び、DL-1（Active）と PR #5626 を挙げて、何も変えずに確かめた。
- **食い違わない依頼**：B も 3 回とも、止まらずにその 1 か所だけを直した（誤って止める例は 0）。振る舞いを変えない文書の修正なので `check` は呼ばれず、時間の差は数秒だった。

## 読み方の注意

- 依頼は 2 種類、回数は 5 回と 3 回、リポジトリは 1 つ、モデルは 1 系統だけ。差ははっきりしているが、ほかのリポジトリや依頼でも同じとは限らない。
- 判定は `git diff` で機械的に行い、止まったかどうかと引用した判断は会話の文面で確かめた。
- B が速いのは、変更に進まずに止まったため。
- B の Decision log は、私たちが掘り起こしたもの 1 件だけ。判断が記録されていない場所では、B も A と同じように振る舞いうる。
