# 照合（check）と記録（record）

過去の判断を、これからの設計・実装・テストにつなぐ。check は判断の前に、record は判断が決まったときに回す。

## check：変える前に、関係する判断を照らす

1. 変える場所を決める。差分があれば `git diff --name-only`（PR なら `git diff --name-only <base>...HEAD`）、計画だけなら言われたパスと、変える識別子・設定名。
2. `python3 .claude/skills/decision-log/scripts/build_index.py <置き場所> --related <パス>… --words <言葉>,<言葉>` で関係する Decision log を挙げる（Kiro は `.kiro/skills/…`）。当たったものだけ全文を読む。
3. 報告する。書かない。止めない（進めるかは人が決める）。
   - **守っている判断**：当たった `Active` の Decision log ごとに、何を守っているかと、理由（記録ありなら出典、不明ならそう書く）。
   - **食い違うおそれ**：計画や差分が `Active` の中身を変える・戻すなら、その箇所と、確かめる問い（誰に聞くか）。決めつけない。
   - **先に答えが要る問い**：当たった Decision log の「分かっていないこと」のうち、この変更に関わるもの。
   - **テスト**：守っている判断を確かめるテストがあるか（`git grep -n <識別子>`）。なければ、足す候補として挙げる。
   - 当たりが 0 件なら「記録された判断はない」と書く。判断がなかったとは限らないので、大事な変更なら `audit` で履歴を掘る候補として挙げる。

## record：決まった判断を、同じ PR に記録する

1. 決めた内容、理由、ほかの案、決めた人、日付を、会話・PR の本文・設計のメモから集める。足りなければ人に聞く。推測で埋めない。決めるのは人で、AI は書き留めるだけ。
2. check で当たった Decision log と同じ流れなら、ファイルの末尾（参照の定義より後）に `## 追記 YYYY-MM-DD` で足す（起きたことの行と、変わったなら `Superseded：…`）。別の判断なら新しい Decision log にし、起きたことの行で古い方を `DL-<番号>` と書く。
3. 形は [format.md](format.md) のとおり。起きたことの行は、PR がまだなら `（ブランチ <名前>）` と書く。理由の 1 行目は `記録あり：<要約>（<決めた人 @アカウント>、<会話・PR の本文など> YYYY-MM-DD）`。決定の言葉が書かれていれば引用する。ステータスは `Active：`、`checked` はいまの `HEAD`。
4. 索引を作り直して `--check` を通し、変更と同じ PR に入れる（コードと判断が一緒にマージされる）。
