- ファイル名は `0001-retry-limit.md`。番号はフォルダーの最大の次。文中では `DL-1` と書く。
- `checked` は調べたときの `HEAD`。「いま」はそのコミットで何が本当かを 1〜2 文で書き、コードの行にリンクする（`/blob/<ハッシュ>/<パス>#L12`）。
- 起きたことは変更ごとに 1 行：日付（JST）、何が変わったか（値は前後を書く）、PR と関わった人。
- 理由の 1 行目は `記録あり：<要約>（<どこに書かれていたか>）`、`推測：<内容>`、`不明。` のどれか。本文に AI の印（`Generated with Claude Code` など）があれば出典に添え、人の判断と合っているかを問いに足す。
- 分かっていないことには、知っていそうな人への問いを書く。なければ「なし」。
- 後の変化や答えは末尾に `## 追記 YYYY-MM-DD` で足す。理由が分かったら 1 行目を `**分かった**（YYYY-MM-DD）：「<問い>」`、取り下げるなら `**終了**（YYYY-MM-DD）：<理由>` にする（索引が読む）。分類と `checked` はフロントマターを直す。
- リポジトリが英語なら英語で書く：`**Now** (<commit>):`、`## What happened`・`## Reason`・`## Open questions`、`Documented:`・`Inferred:`・`Unknown.`、`## Addendum`、`**Answered**`・`**Retired**`。

## 分類

`category` に 1 つ付ける。迷ったら、変更がいちばん守ろうとしているもの。

| `category` | 見出し | 中身 |
|---|---|---|
| `architecture` | 設計・構成 | 分割と統合、依存の向き、採用する技術、基盤の移行 |
| `data` | データの意味・持ち方 | スキーマ、値の意味と単位、保存先、保持期間（個人情報は privacy） |
| `security` | 認証・権限・セキュリティ | 認証方式、権限の境界、秘密情報、署名と検証、暗号化 |
| `privacy` | 個人情報 | 個人情報を集めるか、どこに出す・送る・残すか（ログ・送信先・保持期間）、マスキング |
| `compatibility` | 互換性・外部との約束 | 公開 API、形式、バージョン、廃止 |
| `reliability` | 性能・信頼性 | 負荷や障害のときの振る舞い。タイムアウト、リトライ、上限、キャッシュ、縮退 |
| `release` | リリース・運用 | デプロイの手順、フラグ、環境、監視・アラートと通知先、ログ・トレースの出し方 |
| `engineering` | 開発の決まり | CI の必須チェック、テストの方針、lint・コードの規約、ブランチの運用 |
| `cost` | コスト | インスタンスやプランの大きさ、サンプリングの割合、コストのための削減や上限 |
| `product` | プロダクトの方針 | 仕様の線引き、やらないと決めたこと |
| `other` | その他 | どれにも当たらないもの。多ければ分類を見直す |
