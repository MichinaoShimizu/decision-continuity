# Decision log の書き方（`write` のときに読む）

## 目次

- ファイルの形

- 保存と索引：[save.md](save.md)
- 監査の記録
- 英語で書くとき

## ファイルの形

- ファイル名は `0001.md` か `0001-auth-pkce.md`。先頭の 4 桁が番号で、フォルダーの中で最大の番号の次を使う。ファイル名に `DL-` は付けない（`DL-1.md` にしない）。
- Decision log を指すときは `DL-1` と書き、`#1` とは書かない（GitHub が issue・PR へのリンクにするため）。
- 先頭にフロントマター、その下に `# [<リポジトリ名>] <何が変わったか>`、その下に本文を置く。本文の最初に「いま」の 1 行を置く。
- リンクの URL は本文の最後（追記より前）に参照の定義としてまとめ、本文には `[PR #101][pr101]` の形で書く。行が短くなり、エディタや差分でも読める。
- 追記は末尾に `## 追記 YYYY-MM-DD（書いた人）` の見出しで足す。最初の追記の前にだけ `---` を置く。前の行は書き換えない。同じ日に 2 つ足すときは、見出しの括弧に中身を添えて分ける（`（書いた人、再確認）`）。

## ファイル全体の例

````markdown
---
kind: log
category: reliability
keywords: [MAX_RETRIES, retry, backoff]
checked: abc1234
---

# [payment-api] リトライの上限が 3 から 5 になった

> 過去の観察である。決定ではなく、何も縛らない。

**いま**（abc1234）：上限は 5 のまま。待ち方は指数バックオフ。理由は分かっていない。

## 起きたこと

- C1 2025-03-04 いまも同じ：リトライの上限が 3 から 5 になった（テストも変更、ドキュメントは変更なし）。履歴：[PR #101][pr101] ／ 現在：[`client.py:12`][c12]
- C2 2025-03-04 置き換え済み：失敗時は固定 1 秒待つようになった。履歴：[PR #101][pr101] ／ 現在：[PR #140][pr140] で指数バックオフに変わった（42 日後）

## 理由

不明（記録に書かれていない）。

## 関わった人

PR の記録から。決めた人とは限らない。

- PR #101：作成 @alice（2025-03-03）、承認 @bob（2025-03-04）、マージ @bob（2025-03-04）
- PR #140：作成・マージ @alice（2025-04-15）。レビューと承認は見えない

## 分かっていないこと

- なぜ 5 にしたか。障害対応か、相手先の要望か（@alice に聞く）。

## 元の場所

- （上で触れていない出典だけ。例：議論のあった issue、開けなかった Slack や Notion のリンク。開けなかったものは「未読」と添える。なければこの見出しごと書かない）

## 関係する記録

- （関係する Decision log を `DL-3` の形で。なければこの見出しごと書かない）

[pr101]: <PR #101 の URL>
[pr140]: <PR #140 の URL>
[c12]: <client.py の 12 行目の URL（/blob/abc1234/…#L12）>
````

## 書き方

- **文体**：である調。タイトルで言ったことを本文で繰り返さない。同じリンクやリポジトリ名を何度も書かない。
- **いま**：本文の最初に `**いま**（<基準のコミットの短いハッシュ>）：<1〜2 文>` を置く。基準のコミットで何が本当か、理由は分かっているかを、「起きたこと」を読まなくても分かるように書く。履歴の要約にしない。
- **見出し**：タイトルは `#`、本文の節は `##`（太字を見出しの代わりにしない）。節の順は例のとおり。中身のない節は書かない。「理由」と「分かっていないこと」は、ないなら「不明」「なし」と書いて残す。
- **起きたこと**：変更ごとに 1 行。`C<番号> <日付 YYYY-MM-DD（JST）> <状態>：<何が変わったか>。履歴：<リンク> ／ 現在：<リンク>`。状態は「いまも同じ」「置き換え済み」「一部置き換え済み」「競合」「履歴のみ」のどれか。番号は Decision log の中で一意にし、振り直さない。日付は索引が読む。`build_index.py --check` が状態の語・「履歴：」と「現在：」・番号の重なりを確かめる。
  - 値が変わったなら前後を書く（`3 から 5`）。「増やした」「調整した」だけにしない。
  - 同じ変更でテストやドキュメントが変わったかを、差分で見えたとおりに括弧で添える（`（テストも変更、ドキュメントは変更なし）`）。意図の推測は書かない。
  - 置き換え済み・一部置き換え済みは、「現在」に置き換えた変更へのリンクと、何日後かを書く（`PR #140 で指数バックオフに変わった（42 日後）`）。
- **理由**：1 行目は「記録あり（議論）：<要約>（<出典>）」「記録あり（本文）：<要約>（<出典>）」「記録あり（本文・AI）：<要約>（<出典>）」「記録あり（差分）：<要約>（<出典>）」「推測：<内容>」「不明（記録に書かれていない）」のどれか。議論はレビュー・issue・行のコメントでの作成者以外とのやりとり、本文は PR の本文とコミットメッセージ、AI は本文に AI の印があるとき（文体からは推測しない）、差分はコードのコメントや同じ PR で変わった CHANGELOG・ドキュメント。他の案が書かれていれば 2 行目から書く。1 行目は索引が読む。
- **関わった人**：PR ごとに 1 行。作成した人とマージした人が同じで、レビューも承認もないときは `PR #140：作成・マージ @alice（日付）。レビューと承認は見えない` と 1 行にまとめ、同じ形の PR は `PR #140・#141：…` と並べてよい。作成（`author`・`createdAt`）、承認したレビュー（`reviews` の `APPROVED`・`submittedAt`）、マージ（`mergedBy`・`mergedAt`）。役割は PR に書かれているときだけ `@bob（SRE）` と添える。git だけのときは、コミットの author と日付を書き「レビューは見ていない」と添える。決めた人を書けるのは、決定の言葉と一緒に書かれているときだけである。
- **リンク**：PR・issue・コミット・コードの行はリンクにする。PR は API の `url`。コミットとコードの行は `git remote get-url origin` から作り、ハッシュで固定する（`/commit/<完全なハッシュ>`、`/blob/<ハッシュ>/<パス>#L12`。GitLab は `/-/` を挟む）。作れなければ「リンクなし」と添える。「現在」のリンクはなるべく行の範囲まで付ける（`#L12` か `#L12-L20`）。`build_index.py --stale` はその範囲に当たる変更だけを数えるので、ファイル単位のリンクより要再確認が出すぎない。URL は本文の最後に参照の定義（`[pr101]: <URL>`）としてまとめ、本文では `[PR #101][pr101]` と書く。定義の名前は `pr101`・`c12` のように短くする。
- **フロントマター**：ツールが読む項目だけを置く。`kind`・`category` は索引が読む。`checked` は基準のコミットのハッシュで、`--stale` が比べる起点になる（あとで「再確認」の追記を足すと、そのコミットが起点になる）。`checked` があると、`--check` は「いま」の行も確かめる。`keywords` は、次に decision-log を回したときに差分を洗う言葉に加わる（investigation.md の手順 1）。本文に出てこないが差分に実際に出てくる言葉（識別子、設定名、テーブル名、言い換え）を、1 行の `[a, b]` で書く。

## 追記の印

追記の 1 行目を次の印で始めると、索引やスクリプトが読む。それ以外の追記は印なしで書く（例：「C1 の状態を競合に変更：理由、証拠」）。

| 印 | 使うとき | 2 行目から |
|---|---|---|
| `**分類を更新**（YYYY-MM-DD）` | 分類を直す | `category: <新しい分類>` |
| `**分かった**（YYYY-MM-DD）：「<分かっていないことの問い>」` | 理由が分かった | 答え、答えた人（アカウント名）、元の場所のリンク。なければ「元の場所なし」 |
| `**終了**（YYYY-MM-DD）：<理由>` | 取り下げる（重複、誤りなど） | なし |
| `**再確認**（YYYY-MM-DD、<コミット>）` | 「現在」を確かめ直した（[recheck.md](recheck.md)） | `**いま**：<1〜2 文>` と、状態が変わった C ごとに 1 行（`C1：いまも同じ → 置き換え済み。[PR #140][pr140] で変わった（42 日後）`）。変わらなかった C もまとめて書く（`C2・C3 はいまも同じ`）。`--stale` はこのコミットから比べる |

「分かった」の答えに、決定の言葉と決めた人まで含まれていれば、報告の「決定の候補」にも回す。

### 追記にするか、新しい Decision log にするか

追記に足すのは、印の付くもの（分類の更新、分かった、終了、再確認）と、同じ流れの小さな後の変化（C 行で 3 行まで）だけにする。それを超える後の変化や、別の判断に広がったものは新しい Decision log にし、新しい方の「関係する記録」に古い方を書き、古い方には追記で `DL-<番号> に続く` と書く。追記が長くなると、本文の状態と追記の状態が食い違ったまま並び、読む人が最後まで追わないと「いま」が分からなくなるため。

## 監査の記録

全体の監査を頼まれ、時系列と候補の一覧（ledger）を残すように言われたら、同じ置き場所に `[<リポジトリ名>] 監査 YYYY-MM-DD`（フロントマターは `kind: audit`）を書く。中身は範囲、広さと深さ、確かめた手順、未調査の範囲である。

## 英語で書くとき

`lang=en` か、リポジトリの指示（`CLAUDE.md`・`AGENTS.md` など）が英語を求めるときは、本文を英語で書く。形は日本語と同じで、決まった言葉だけを次のように置き換える。索引のスクリプトは両方を読み、索引の言語はいまの索引に合わせる（新しく作るときは多いほうの言語）。1 つの置き場所の中で言語を混ぜない。

| 日本語 | 英語 |
|---|---|
| `# [<リポジトリ名>] <何が変わったか>` | `# [<repo>] <what changed>` |
| `> 過去の観察である。決定ではなく、何も縛らない。` | `> A past observation, not a decision. It binds nothing.` |
| `## 起きたこと`・`## 理由`・`## 関わった人`・`## 分かっていないこと`・`## 元の場所`・`## 関係する記録` | `## What happened`・`## Reason`・`## People involved`・`## Open questions`・`## Sources`・`## Related logs` |
| `- C1 2025-03-04 いまも同じ：…。履歴：… ／ 現在：…` | `- C1 2025-03-04 Still true: …. History: … / Now: …` |
| 状態：いまも同じ・置き換え済み・一部置き換え済み・競合・履歴のみ | Still true・Replaced・Partly replaced・Conflict・History only |
| `**いま**（<コミット>）：` | `**Now** (<commit>):` |
| `**再確認**（YYYY-MM-DD、<コミット>）` | `**Rechecked** (YYYY-MM-DD, <commit>)` |
| `記録あり（議論）：`・`記録あり（本文）：`・`記録あり（本文・AI）：`・`記録あり（差分）：` | `Documented (discussion):`・`Documented (description):`・`Documented (description, AI):`・`Documented (diff):` |
| `推測：`・`不明（記録に書かれていない）。` | `Inferred:`・`Unknown (not recorded).` |
| 関わった人の「作成・承認・マージ」 | opened・approved・merged |
| `## 追記 YYYY-MM-DD（書いた人）` | `## Addendum YYYY-MM-DD (author)` |
| `**分類を更新**（YYYY-MM-DD）` | `**Category updated** (YYYY-MM-DD)` |
| `**分かった**（YYYY-MM-DD）：「<問い>」` | `**Answered** (YYYY-MM-DD): "<question>"` |
| `**終了**（YYYY-MM-DD）：<理由>` | `**Retired** (YYYY-MM-DD): <reason>` |
