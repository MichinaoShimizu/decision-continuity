# Decision log の書き方（`write` のときに読む）

## ファイルの形

- ファイル名は `0001.md` か `0001-auth-pkce.md`。番号はフォルダーの中で最大の番号の次。`DL-` は付けない。
- 文中で指すときは `DL-1` と書く（`#1` は GitHub が issue へのリンクにする）。
- 本文は書いたあと書き換えない。訂正と後の変化は、末尾の `## 追記 YYYY-MM-DD（書いた人）` に足す（最初の追記の前にだけ `---`）。フロントマターは直してよい。

## 例

````markdown
---
kind: log
category: reliability
keywords: [MAX_RETRIES, retry, backoff]
checked: abc1234
---

# [payment-api] リトライの上限が 3 から 5 になった

> 過去の観察である。決定ではなく、何も縛らない。

**いま**（abc1234）：上限は 5 のまま。待ち方は指数バックオフ。理由は分かっていない。

## 起きたこと

- C1 2025-03-04 いまも同じ：リトライの上限が 3 から 5 になった（テストも変更、ドキュメントは変更なし）。履歴：[PR #101][pr101] ／ 現在：[`client.py:12`][c12]
- C2 2025-03-04 置き換え済み：失敗時は固定 1 秒待つようになった。履歴：[PR #101][pr101] ／ 現在：[PR #140][pr140] で指数バックオフに変わった（42 日後）

## 理由

不明（記録に書かれていない）。

## 関わった人

PR の記録から。決めた人とは限らない。

- PR #101：作成 @alice（2025-03-03）、承認 @bob（2025-03-04）、マージ @bob（2025-03-04）
- PR #140：作成・マージ @alice（2025-04-15）。レビューと承認は見えない

## 分かっていないこと

- なぜ 5 にしたか。障害対応か、相手先の要望か（@alice に聞く）。

[pr101]: <PR #101 の URL>
[pr140]: <PR #140 の URL>
[c12]: <client.py の 12 行目の URL（/blob/abc1234/…#L12）>
````

節は例の順に置く。上で触れていない出典（議論のあった issue、開けなかった Slack などは「未読」と添える）があれば `## 元の場所`、関係する Decision log があれば `## 関係する記録` を「分かっていないこと」の後に足す。

## 書き方

- **文体**：である調。タイトルで言ったことを繰り返さない。
- **いま**：`**いま**（<基準のコミット>）：` に続けて、いま何が本当か、理由は分かっているかを 1〜2 文で書く。
- **起きたこと**：変更ごとに 1 行。`C<番号> <日付（JST）> <状態>：<何が変わったか>。履歴：<リンク> ／ 現在：<リンク>`。
  - 状態は 3 つ。**いまも同じ**（基準のコミットにそのまま残る）、**置き換え済み**（一部でも後の変更で変わった。「現在」に変えた変更と何日後かを書く）、**履歴のみ**（基準のコミットに該当するコードがない）。
  - 値は前後を書く（`3 から 5`）。テストやドキュメントが同じ変更で変わったかを括弧で添える。
  - 番号は振り直さない。
- **理由**：1 行目は次のどれか。索引が読む。他の案が書かれていれば 2 行目から。
  - `記録あり：<要約>（<出典>）`。出典はどこに書かれていたか（`@bob のレビュー`、`PR #101 の本文`、`client.py のコメント` など）。本文に `Generated with Claude Code`・`Co-Authored-By: Claude` などの印があるか作成者がボットなら、出典に「AI の印あり」と添え、「分かっていないこと」に「この理由は人の判断と合っているか」の問いを足す（文体からは推測しない）。
  - `推測：<内容>`
  - `不明（記録に書かれていない）。`
- **関わった人**：PR ごとに 1 行。作成（`author`・`createdAt`）、承認（`reviews` の `APPROVED`）、マージ（`mergedBy`・`mergedAt`）。作成とマージが同じでレビューがなければ `作成・マージ @alice（日付）。レビューと承認は見えない` と 1 行に。git だけなら、コミットの author と「レビューは見ていない」。
- **リンク**：PR は API の `url`。コミットとコードは `git remote get-url origin` から作り、ハッシュで固定する（`/blob/<ハッシュ>/<パス>#L12-L20`。GitLab は `/-/` を挟む）。「現在」は行の範囲まで付けると、`--stale` が出すぎない。URL は本文の最後に `[pr101]: <URL>` としてまとめる。
- **フロントマター**：`kind: log`、`category`（[categories.md](categories.md)）、`keywords`（本文にないが差分に出てくる識別子・設定名。次の回の洗い出しに加わる）、`checked`（基準のコミット。`--stale` の起点）。

競合（PR の本文と差分が食い違うなど）は状態にしない。差分で確かめたことを C 行に書き、食い違いを「分かっていないこと」と報告の先頭に書く。

## 追記

印の付く追記は 2 つだけ。索引が読む。

| 1 行目 | 使うとき | 2 行目から |
|---|---|---|
| `**分かった**（YYYY-MM-DD）：「<問い>」` | 理由が分かった | 答え、答えた人、元の場所のリンク（なければ「元の場所なし」） |
| `**終了**（YYYY-MM-DD）：<理由>` | 取り下げる（重複、誤り） | なし |

ほかは印なしで書く（例：「C1 は置き換え済みになった：PR #140」）。分類を直すときはフロントマターの `category` を直す。確かめ直したときは [recheck.md](recheck.md)。

同じ流れの小さな後の変化（C 行で 3 行まで）は追記に足す。それより大きいものや別の判断は新しい Decision log にし、`## 関係する記録` で古い方を指し、古い方に `DL-<番号> に続く` と追記する。

## 監査の記録

全体の監査で、時系列と候補の一覧を残すように言われたら、同じ置き場所に `[<リポジトリ名>] 監査 YYYY-MM-DD`（`kind: audit`）を書く。範囲、広さと深さ、確かめた手順、未調査の範囲を書く。

## 英語で書くとき

`lang=en` か、リポジトリの指示が英語を求めるときは英語で書く。形は同じで、決まった言葉を置き換える。1 つの置き場所で言語を混ぜない。

| 日本語 | 英語 |
|---|---|
| `> 過去の観察である。決定ではなく、何も縛らない。` | `> A past observation, not a decision. It binds nothing.` |
| `**いま**（<コミット>）：` | `**Now** (<commit>):` |
| `## 起きたこと`・`## 理由`・`## 関わった人`・`## 分かっていないこと`・`## 元の場所`・`## 関係する記録` | `## What happened`・`## Reason`・`## People involved`・`## Open questions`・`## Sources`・`## Related logs` |
| `- C1 2025-03-04 いまも同じ：…。履歴：… ／ 現在：…` | `- C1 2025-03-04 Still true: …. History: … / Now: …` |
| いまも同じ・置き換え済み・履歴のみ | Still true・Replaced・History only |
| `記録あり：`・`推測：`・`不明（記録に書かれていない）。` | `Documented:`・`Inferred:`・`Unknown (not recorded).` |
| 作成・承認・マージ | opened・approved・merged |
| `## 追記 YYYY-MM-DD（書いた人）` | `## Addendum YYYY-MM-DD (author)` |
| `**分かった**（YYYY-MM-DD）：「<問い>」`・`**終了**（YYYY-MM-DD）：<理由>` | `**Answered** (YYYY-MM-DD): "<question>"`・`**Retired** (YYYY-MM-DD): <reason>` |
