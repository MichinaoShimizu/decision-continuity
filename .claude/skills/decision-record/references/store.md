# 置き場所（decision-record）

## 置き場所（records/ の Markdown）

記録は記録のリポジトリの `records/` に、1 件 1 ファイルの Markdown で置く。変更は PR で入れ、既定のブランチにマージされたら保存されたことになる。

| 種類 | フォルダー |
|---|---|
| 決めたこと | `records/decisions/`（Decisions） |
| 決め方（kind: flow） | `records/decision-flows/`（Decision flows） |
| 過去に起きた変更の観察（縛らない） | `records/decision-logs/`（Decision logs。書式は `decision-log`） |
| 「なんで？」の質問 | `records/questions/`（Q&A） |

- **番号**：ファイル名の先頭の 4 桁（`0042.md`、`0042-no-pii-in-logs.md`）がそのまま番号。番号はフォルダーをまたいだ通し番号で、`records.py create` が次の番号を振る。手で作るときも、いちばん大きい番号の次にする。
- **番号の書き方**：記録を指すときは種類の接頭辞を付ける。決定は `DR-42`、決め方は `DF-12`、Decision log は `DL-17`、Q&A は `Q-30`。`#42` とは書かない（GitHub が issue・PR #42 へのリンクにしてしまうため）。`records.py show` と `comment` は `DR-42` でも `42` でも受け取る。
- **ファイル**：先頭に記録データ（YAML のフロントマター。`---` と `---` で挟む）、その下に `# タイトル`、本文、さらにその下に `---` と「追記」が続く。ファイルを消したり、名前やフォルダーを変えたりしない。
- **タイトル**：何を決めたかが分かる一行。
- **関係**：項目として持つのは `superseded_by`（置き換え）と `approved_via`（使った決め方）だけ。前提にしている決定や関連する決定は、本文に `DR-42` の形で書く。逆向きのつながりは `records.py show` が「参照している記録」として出す。
- **本文**：人が読む文章。記録データはフロントマターに置き、本文には書かない。形は [record-format.md](record-format.md) の「本文の書き方」。
- **追記**：コメントにあたるもの。ファイルの末尾に `## 追記 YYYY-MM-DD（書いた人）` の見出しで足す（`records.py comment` が付ける）。前の行は変えない。
- **状態**：[SKILL.md](../SKILL.md#状態) の「状態」のとおり。終わらせるときは「**終了**」の追記を足す。置き換えたなら「**終了**（YYYY-MM-DD）：DR-<番号> に置き換え」、やめたなら「**終了**（YYYY-MM-DD）：やめた。（理由）」。
- **Q&A**：答えが付いた質問は「拾う」に回し、新しい DR の `sources` に `asked` としてその Q&A を入れる。
- **読み方**：リポジトリのルートで `python3 .claude/skills/decision-record/records.py <コマンド>` を実行する（絶対パスにしない。許可の設定がこの形で書かれている）。`index --repo <名前>` で探すための一覧、`show <番号>` で本文と追記、`config` で記録のリポジトリの `config.yaml`。記録のリポジトリがほかのリポジトリ（`STORE` の `owner/repo`）なら、読むたびにキャッシュへ最新を取ってくる（`git` で読めること）。終了コード 2 は「読めなかった」で、「記録がない」ではない。
- **書き方**：記録のリポジトリの手元のクローンで、既定のブランチから新しいブランチを切り、`python3 .claude/skills/decision-record/records.py create --category <フォルダー名か種類の名前> --title <タイトル> --body-file <ファイル>`、追記は同じく `comment <番号> --body-file <ファイル>`。ファイルを作れないときは `--body-file -` にして本文を標準入力で渡す。ほかのリポジトリから書くときは `--store <クローンのパス>`（か環境変数 `DR_STORE`）を付ける。`--store` はコマンドの前に置く（`records.py --store <パス> create …`）。書いたら `records.py check --base origin/<既定のブランチ>` を通し、コミットして PR を出す。PR を出したら「PR を出した（マージで保存される）」と、番号とファイルと PR のリンクを伝える。マージ前に「保存した」と言わない。
- **番号がぶつかったとき**：ほかの PR が先に同じ番号でマージされたら、自分の側のファイルの番号を振り直す（`check` が知らせる）。マージ前のファイルなので書き換えてよい。
- **書けないとき**：記録のリポジトリに PR を出す手段がない環境では、タイトルと本文をそのまま貼れる形で返し、「まだ保存していません」と明記する。ほかのリポジトリに書いて代わりにしない。
