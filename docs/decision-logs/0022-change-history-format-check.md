# change-history の主な変更と年の要点の形を、スクリプトで確かめることにした

## ステータス

Active：`build_history.py` は、月の主な変更と年の要点が決まった形（`### <分類>` の下に「- 」の行、月の行は末尾に PR かコミット、年の行は末尾に月か期間、日付は略さない）かを確かめ、崩れていればファイルと行と中身を出して終了コード 1 を返す（`skills/change-history/scripts/build_history.py` の `problems`）。分類の並びが decision-log の `format.md` と同じことは `tests/test_docs.py` が確かめる。

## 起きたこと

- 2026-10-19 主な変更と年の要点の形を確かめる `problems` を足し、作り直しと `--check` の両方で崩れを数えるようにした。SKILL.md の手順に、崩れが 0 件になるまで直すことを足した（ブランチ change-history-format-check。作成 @MichinaoShimizu）

## 理由

記録あり：「決まったフォーマットで確実に年表を出力したいがそうなっているか」という問いに、AI が書くところはスクリプトが確かめておらず、崩れた形（見出しのない行、11 種にない分類、`5 月` のような日付、PR のない行）でも `--check` が通ることを示した。確かめる案に @MichinaoShimizu が「進めて」と答えた（会話 2026-10-19）。

ほかの案：AI が書いた中身をスクリプトが直す案は取らなかった（中身の言葉を変えると、推測で足さないという決まり（SKILL.md の決まり 3）に触れる）。

## 分かっていないこと

- 中身が正しいか（PR の番号が本当にその月の一覧にあるか、分類が合っているか）は確かめていない。PR の番号がその月の一覧にあるかまで確かめるか。
- 分類の見出しのない以前の要点は、次に回したときにすべて崩れとして出る。書き直しの手間が大きいリポジトリがあるか。
