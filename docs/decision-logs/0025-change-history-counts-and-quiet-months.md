# change-history の年表の件数を取り込まれた変更まで数え、変更のない月も載せることにした

## ステータス

Active：`build_history.py` の年表の件数は、PR の中のコミットを数えず、PR を通さないブランチの取り込み（`Merge branch '8.1.x'` など）は取り込んだ側の PR と直接のコミットを、中で別の PR をマージした PR はその PR も数え、ブランチ間のマージは 0 と数える（`skills/change-history/scripts/build_history.py` の `size`）。変更のなかった月は `| 2024-01〜2024-02 | 0 | 変更なし |` の行で載せ、変更のなかった年は要点を「変更なし」にする（`readme_page`）。依存の更新に「（依存の更新）」の印を付け、依存の更新・リリース・ブランチ間の取り込みだけの終わった月は、スクリプトが「- 目立った変更なし（…のみ）」と書く（`DEPS_RE`・`quiet`）。

## 起きたこと

- 2026-10-20 年表の件数を、本流の `--first-parent` のコミットの数から、上の数え方に変えた。変更のなかった月と年を年表に載せ、依存の更新の印と、依存の更新・リリースだけの月をスクリプトが書く形を足した。`--list` は、1 コミットだけの PR の中のコミットを、同じタイトルならもう出さない（ブランチ change-history-counts。作成 @MichinaoShimizu）

## 理由

記録あり：「すすめて、3は変更なし、4は正確に」（@MichinaoShimizu、会話 2026-10-20）。Claude が pallets/click（本流 1,384 件、136 か月）で試して挙げた 4 つの改善（`--list` の重なり、依存の更新の印、変更のない月が年表から消える、件数が取り込まれた変更を数えない）に答えたもの。3 は変更のない月を「変更なし」と載せる、4 は件数を正確にする、という決定。click では 2023-07 が 7 件と出ていたが、`Merge branch '8.1.x'` で 25 件の変更が入っていた（直したあとは 32 件）。

ほかの案：変更のない月を 1 か月ずつ行にする案は取らなかった（続いた月は 1 行にまとめた。Claude の判断）。いま進んでいる月は、あとから変更が増えるので、依存の更新だけでもスクリプトは書かない（Claude の判断）。

## 分かっていないこと

- 「正確な件数」を、PR と直接のコミットの数とした（PR の中のコミットは数えない）。PR の中のコミットまで数えたい人がいるか（@MichinaoShimizu に聞く）。
- 依存の更新の見分けは件名の形だけで決める（`Bump x from a to b`・`build(deps):`・`chore(deps):`・`Update dependency x`・`[pre-commit.ci] pre-commit autoupdate`）。ほかの形のボットや、手で書いた依存の更新は印が付かない。

## 追記 2026-10-20（件数は PR と直接のコミット）

- 2026-10-20 年表の件数を、その月にデフォルトブランチへマージされた PR と、PR を通さない直接のコミットの数にした。マージの中身や保守ブランチの取り込みの中まで数えるのをやめた（DL-27。ブランチ change-history-from-prs。作成 @MichinaoShimizu）。依存の更新・リリース・ブランチの取り込みだけの月をスクリプトが書く扱いと、変更のない月を載せる扱いは残した
Superseded：`build_history.py` の `readme_page` は、月の変更の数（`len`）を件数にし、`size` はない（`skills/change-history/scripts/build_history.py`）
